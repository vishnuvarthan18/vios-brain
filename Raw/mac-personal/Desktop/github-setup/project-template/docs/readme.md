# DOCS

The durable written material for this project: how it works, why it is built
this way, what was tried and dropped, and anything referenced often enough to
be worth keeping.

Not for generated output — that goes in `reports/` or `releases/`.

Worth writing down here, because nothing else records it:

- **Decisions and their reasons.** One short file per decision that was close,
  saying what was chosen and what it was chosen over. This is the material that
  is impossible to reconstruct later.
- **References** — vendor documentation, specifications, captures — kept apart
  from what the project documents about itself.
- **Approaches that did not ship.** What was tried, and why it was dropped, so
  the knowledge survives without cluttering `src/`.
