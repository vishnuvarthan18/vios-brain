## 6. One rule was broken: the spacing ladder

Your instruction was **ACDS wins on structure, naming AND values**. For eight spacing tokens, it didn't. The newer system's 10-based ladder replaced ACDS's 4-based one, under the same names:

| Token | ACDS | Now |
|---|---|---|
| `--ac-space-3` | 12px | 10px |
| `--ac-space-4` | 16px | 12px |
| `--ac-space-5` | 24px | 15px |
| `--ac-space-6` | 32px | 16px |
| `--ac-space-7` | 48px | 20px |
| `--ac-space-8` | 64px | 24px |
| `--ac-space-9` | 96px | 30px |
| `--ac-space-10` | 128px | 40px |

`--ac-space-1` (4px) and `--ac-space-2` (8px) are unchanged.

**Blast radius is small.** Of the 101 files the merge left alone, the only ones that reference a re-valued rung are `_ds_manifest.json` and `_adherence.oxlintrc.json` — both generated by the app and rebuilt from source. **No hand-authored ACDS file that survived the merge untouched is affected.**

The problem is semantic rather than visual: `--ac-space-5` now means 15px while ACDS's own documentation says 24px. Anyone building against the old names gets different spacing than they expect.

Everything else in the token layer is either identical, an indirection that resolves to the same value (`--ac-white`, `--ac-border`, `--ac-gray-300/600/900`, `--ac-gutter`), or a lengthened font fallback chain with the same primary family. **No ACDS token was removed.** 59 were added.
