# 05 — Database Security

> Authentication, network lockdown, and credential rotation for Postgres, MongoDB, Redis.

---

## 5.1 PostgreSQL (S1)

- 32+ char random password (generated by `make env-init`)
- `arm_monitoring`: separate read-only user (`pg_monitor` role)
- All connections require password auth — no `trust` entries
- Listens `0.0.0.0:5432` in container — but S1 has no public IP
- UFW + Hetzner firewall restrict to S2, S3, S4 only
- Hardware-level disk encryption (Hetzner NVMe)
- App-level encryption: `GOOGLE_TOKEN_ENCRYPTION_KEY` for OAuth tokens

## 5.2 MongoDB (S1)

- `--auth` flag enforced in start command
- Root: `MONGO_ROOT_USER` / `MONGO_ROOT_PASSWORD`
- `arm_monitoring`: `clusterMonitor` role only (read-only metrics)
- Same network lockdown as Postgres

## 5.3 Redis (S2)

- `--requirepass` with strong password
- Not exposed to host network — all consumers (session service, calendar-be) are co-located on S2
- Only exception: S3's redis-exporter needs access via UFW rule

## 5.4 Credential Rotation (Quarterly)

1. Generate new password
2. Update `.env` on S2 + GitHub Secrets
3. `ALTER USER` on S1 Postgres / `db.updateUser()` on S1 MongoDB
4. Restart app services on S2
5. Verify health checks pass
