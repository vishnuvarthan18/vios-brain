# DECISIONS

The decision record for the design system — what changed, when, why, and the
measurement that forced it.

**This is not the release changelog.** `CHANGELOG.md` at the repo root is
generated by semantic-release from the commit log, per
[git-conventions](https://github.com/aracreate-group/aracreate-conventions/blob/main/git/git-conventions.md).
This file holds the reasoning that a generated changelog cannot: what was
measured, what was rejected, and what was deliberately left alone.

Entries are grouped by the version they landed in, newest first. Versions before
the first release are internal milestones — `VERSION` at the root reads `0.0.1`
until semantic-release cuts one.

## The Claude design system

20 August 2026. Vishnu: *"we need to recreate this on our Claude design system"*
— and, when asked whether to replace the team's existing one, *"we need to make
it separate, not replace or update that."*

So `releases/claude-design-system/` is a **new** design-system project, alongside
ACDS rather than over it.

### It is a generated view, not a fork

The one decision that matters. This repository stays the system; that folder is a
printout of it. `make claude-ds` refreshes the printout; `make test-claude-ds`
compares every copy to its source **byte for byte** and fails the build on any
difference.

Without that gate the arrangement would be indefensible. A copy rots quietly:
someone edits the copy instead of the source, or edits the source and forgets to
refresh, and from then on the two disagree with nobody noticing. That is the exact
failure the ACDS comparison had just spent two days untangling, and repeating it
deliberately would have been absurd.

Copies, refreshed: the two stylesheets, the three scripts, the five asset
folders, both UI kits, and `CLAUDE.md`. Hand-maintained: `styles.css`,
`card.css`, `SKILL.md`, `readme.md`, and the twelve cards.

### No React, and that is a change from ACDS

ACDS shipped thirteen React components with inline styles, and every card loaded
React, ReactDOM and Babel-standalone from a CDN with integrity hashes, then
compiled JSX in the browser to render a button.

Ours are plain HTML on the real bundle. A card is a `<link>` and some markup.

The reason is not taste. Our components *are* CSS classes — a React wrapper would
either duplicate every value inline (two systems, two fixes for every bug) or be
a thin shim that adds a build step, three CDN requests and an in-browser
transpiler in order to write `class="ac-btn"`. And a page Claude generates for
araCreate is HTML; giving it React components to compose from would be giving it
the wrong tool for its own output.

The side effects are all good: the cards work offline, they cannot break when
unpkg changes, and they are readable as the markup you would actually write.

### What is in it

Twelve cards across five groups — **Foundations** (colour, type, space and shape,
and two cards for the signature edge and devices), **Components** (buttons, forms,
display, navigation), **Brand** (logos, imagery), **Deck** (slides).

The signature-edge card is the one ACDS had no equivalent for, which is telling:
it is the most distinctive thing araCreate owns and it had never been given a
page of its own.

Two kits, both real rather than written for the occasion. The website kit **is**
the proof page — a complete araCreate Academy page built with no custom CSS at
all. The deck kit **is** the ten-slide deck. Copying them rather than authoring
examples means the kits cannot be prettier than the system.

And `CLAUDE.md`, generated from `brand-facts.md` plus the Voice section of
`guidance.md`. This is the highest-value file in the bundle and it is not code:
with it in place, anything Claude generates for araCreate cannot say "300
clients", cannot use an emoji, cannot set a heading in Monument Extended, and
cannot invent a ninth group company.

### The licensed typeface stays behind

`build-claude-ds.py` copies five asset folders and deliberately not `fonts/`.
Monument Extended is a commercial licence and this bundle is pushed to a hosted
project; the logo SVGs have the wordmark outlined to vector paths already, so
nothing up there needs it. `check-claude-ds.py` fails if an `.otf` ever appears.

### What the gates found, again

Pointing the existing gates at brand-new files paid immediately:

- **All twelve cards had no `h1` and no `<main>`.** A card is loaded as a real
  document in the pane, so a screen-reader user meets a page with no heading and
  no landmark. Fixed with a screen-reader-only `h1` — except the type card, whose
  own specimen ladder already supplies one, which is why the rule is "exactly
  one" rather than "at least one". `check-claude-ds.py` now enforces it.
- **Three cards skipped a heading level** — `h1` straight to `h3` or `h4`,
  because a card title and a slide title were marked up by how big they look
  rather than where they sit.
- **`docs/decisions.html` had three elements sharing `id="verified"`.** Three
  different headings in this file reduce to the same slug, so two of the three
  anchors went to the wrong place. The generator disambiguates now.
- **The proof page's favicon still said `#2e2e2e`** — a colour this system
  stopped using earlier the same day, sitting in a data URI where no gate looks.

The contrast and accessibility gates now **glob rather than list**, so a new page
or card is covered the moment it exists rather than the moment someone remembers
to add it. The sweep went from 10 pages to 26, and from 2,511 text elements to
3,620, still at zero failures.

### The push is Vishnu's to run

`/design-sync` is reserved for explicit invocation by the person, not the agent,
and working around it via the underlying tool would defeat the point of that
reservation. So this repository's job ends at a folder that passes its own gate,
and the last step is one command typed by hand.

## The ACDS merge

20 August 2026. Vishnu handed over the design system his team had built earlier
(ACDS), which was assembled from the araCreate Brand Guidelines v1.0, the brand
asset library and the production Webflow export. The instruction was to take what
was missing from it, and nothing else.

Seven things came across. Two did not.

### 1 · Brand facts became a document nobody may improvise around

`docs/brand-facts.md`. The figures, the eight group companies with their legal
suffixes, the three verticals with their fixed couplets, the four values, the
Berlin address, the founder and the founding year.

This is the highest-value thing in the whole merge and it is not code. A design
system generates placeholder copy, and placeholder copy ships. `300 clients` is
a plausible-looking sentence and a false claim; the fact is `300+ clients`, and
**the plus sign is what makes it true.** The document says so explicitly, lists
what is *not* a fact, and tells anyone needing filler to use obvious filler —
`Client name`, `00+` — because a visible placeholder gets replaced and a
plausible invention does not.

Every figure on `docs/deck.html` now traces to this file.

### 2 · Four colour corrections, and the palette got its real names

The first audit read the colours off the *rendered site* and merged what it
found into derived values. The Brand Guidelines and the live Webflow variables
both disagreed, and on a question of brand values the guidelines win over a
measurement.

| Was | Is | Which is |
| --- | --- | --- |
| `#2e2e2e` charcoal | **`#222222`** | Brand black. The measured value was a merge of #222, #252525 and #333 — an average of three things, matching none of them. |
| `#c8c8c8` | **`#cecece`** | The hairline Stroke, as specified. |
| — | `#fdf3d8` | Golden Soft, the pale gold wash. The alternating page band had **no token at all**, so a consumer had to write the hex by hand. |
| "Duotint leftover" | `#2e419e` | Not a leftover. It is the duotint photo wash — the reason araCreate photography reads warm-grey rather than full colour. The earlier audit deleted it as a stray Webflow default. |

The primitives now carry the guidelines' own names — `--ac-golden-sun`,
`--ac-graphite-gray`, `--ac-brand-black`, `--ac-stroke`, `--ac-canvas`. The old
names are aliases pointing at them, so nothing written before today had to
change.

Correcting brand black **improved** every contrast figure that touches it: text
on the page went from 12.57:1 to 14.72:1, white on a dark band from 13.58:1 to
15.91:1, the button label on gold from 8.11:1 to 9.51:1. `#2e2e2e` survives as
`--ac-charcoal`, used only for translucent overlays, where a shade off pure
black reads as dimmed rather than switched off.

### 3 · The asset library, documented

32 logos, 17 isometric icons, 8 illustrations, 5 duotint images, 2 brand
applications, and the two Monument Extended OTFs — copied in, and then
`docs/assets.md` written for them, because an undocumented asset library is a
folder.

**The logo variants are not interchangeable, and this took rendering all of them
to establish.** Each carries a coloured chip behind CREATE, sized for one
specific background. `-t-w-b-g` on brand black shows its graphite chip as a grey
rectangle that looks exactly like a rendering fault. `aracreate-logo-negative`
is for placing over imagery, not for dark backgrounds, despite the name. The
table in `assets.md` lists only the combinations that survived being looked at.

Monument Extended is **not in the bundle.** It is a commercial licence, linking
it publishes the `.otf` to every visitor, and the logo SVGs have the wordmark
outlined already so almost nothing needs it. `src/wordmark-font.css` is an
opt-in with one selector, and `.gitignore` now excludes `*.otf` — so a fresh
clone falls back to Arial Black, which is the safe failure.

### 4 · Voice

`docs/guidance.md` gained a Voice section: person ("we" for araCreate, "you" for
the client), sentence case for headlines with wide-tracked caps reserved for
labels, the numbered section eyebrows, the fixed phrasings, and the five things
the brand never does — no emoji anywhere, no exclamation marks in body copy, no
invented facts, no "click here", no shouted sentences.

The system decided how a page looks. Nothing decided how it sounds, and a page
built correctly and written in the wrong voice is still off-brand. It is also
the only failure no gate could catch — until the adherence gate, which now flags
emoji and vague link text.

### 5 · A display tier, three shadows, and the site’s real container width

- **Display sizes.** The heading ladder tops out at 36px, right for a page
  heading and far too small for a hero or a slide title. `--ac-size-display-sm`
  through `-xl` (28/36/48/64) sit above it. The heading ladder is unchanged. The
  deck could not be built without this.
- **Shadows: one became three.** The original note said "exactly one shadow,
  because a system with five ends up with fifteen." The instinct was right and
  the count was wrong — a hovered card, a dropdown and a modal sit at three
  genuinely different distances from the page, and collapsing them meant a modal
  looked no further away than a hovered card. `--ac-shadow-lift`, `-float`,
  `-overlay`. There is still deliberately **no resting shadow**: a card at rest
  is flat, and the signature edge is what separates it from the page.
- **`ac-container--narrow`, 940px.** What every `.container` on aracreate.group
  actually measures. The 1200px default stays, because changing it would restyle
  every page already reviewed and approved.

### Also: eighteen raw font sizes, found while doing the above

Rule one of this system is *never write a raw value*, and the system was
breaking it eighteen times — `font-size: 42px` in the stat, `11px` in the label,
`10px` in the avatar initials, and so on. Naming them changed nothing on screen:
`--ac-size-micro`, `-label`, `-ui`, `-lead`, `-figure`, `-quote`, each the exact
size it already was. Rounding them to the existing ladder would have been a
visual change dressed up as tidying.

The system now writes no raw font size anywhere.

### 6 · The adherence gate — the first one that leaves this repository

`tests/check-adherence.py`, and `make adhere PATH_=../aracreate-academy`.

ACDS shipped 25 oxlint rules policing consumer code. That approach does not port
— theirs polices JSX props, ours has no components to have props. But the *idea*
ports exactly, and it was the one thing ACDS had that this system had no answer
to: five gates that all graded the system, and nothing that graded the people
using it.

Ten rules on any HTML or CSS: raw colours, raw sizes on properties a token
exists for, fonts outside the three families, composed shadows, raw durations,
`!important`, unknown tokens, unknown classes, emoji, and link text that says
nothing on its own.

**The vocabulary is read live out of `src/*.css`**, so a rule can never disagree
with the system — add a token and it is legal on the next run, with no edit to
the gate. `src/manifest.json` holds the same list machine-readably; ACDS had one
of those too, and this system did not.

The rule that earns its keep is **unknown class**. `class="ac-crad"` is not an
error in CSS. It simply does nothing, the page looks subtly wrong, and there is
nothing to grep for.

### 7 · The deck

`src/deck.css`, `src/deck.js`, `docs/deck.html`. Ten layouts.

The araCreate deck is the richest piece of brand design the company owns and it
lived in a PDF — unthemeable, unsearchable, unlinkable, impossible to keep in
step with a rebrand, and requiring every figure to be retyped into every
proposal. Which is how a slide ends up saying "300 clients".

A slide is 16:9 and `container-type: size`, so every size inside is written in
`cqw` — one percent of the slide’s own width. The deck is therefore
resolution-independent with no media queries and no JavaScript measuring
anything: the same markup is a thumbnail, a projector slide, and a landscape PDF
page. `deck.js` is optional and adds only arrow keys and fullscreen.

It is **not in the bundle**. Most sites never present anything.

Two things the gates found immediately, both worth recording:

- **White on gold is 1.67:1.** The printed deck reverses emphasised words out in
  white on the gold title slide, and the first version of `deck.css` copied that
  with a comment claiming it was acceptable at 105px. It is not acceptable at
  any size — 3:1 is the *large-text* threshold and this misses it by nearly
  half. Emphasis is weight now, which survives greyscale printing and a
  projector with the contrast wound down.
- **A coloured slide must carry its surface class.** `base.css` colours headings
  explicitly, so a heading ignores the colour inherited from the slide and
  renders graphite-on-gold at **4.45:1** — the same 0.05-below-threshold miss
  this system already repaired once for buttons. `check-deck.js` fails the build
  on the omission, because a silent 4.45:1 is worse than a visible mistake.

`check-deck.js` also measures the one failure a deck has that nothing else can
see: **content taller than the slide.** A slide clips silently — no error, no
scrollbar, nothing wrong in the HTML — so it is measured at three widths,
because a heading that fits on one line at 1280px wraps to two at 900px and
pushes the last paragraph out of frame.

### What was deliberately NOT taken

- **Their React components.** Thirteen core plus two content components, written
  as JSX with inline styles. This system is platform HTML and CSS: `<details>`
  for an accordion, `<dialog>` for a modal, real inputs with `appearance: none`.
  Adopting theirs would mean two component libraries, and a React component
  cannot be dropped into a Webflow page.
- **Their colour values that fail contrast.** `--ac-text-muted: #8a8a8a`
  measures 3.24:1 on the canvas. This system’s muted text is `#6f6f6f` at
  4.61:1, which is the lightest grey that passes. Their status colours were
  likewise not adopted.
- **Their radii.** ACDS specifies cards at 20px, panels at 9px, inputs at 4px.
  Everything here is square, by Vishnu’s decision of the same morning, and that
  decision stands as a deliberate override of the guideline rather than an
  oversight.

### One thing found in their favour, worth saying plainly

Their `readme.md` is a better piece of work than anything this system had in its
place: brand guidelines, company facts, voice, the live Webflow component
inventory with instance counts, the page architecture, the DTF sub-brand. Five of
the seven items above exist because that file said what it knew. A system that
documents its brand as well as its buttons is doing something this one was not.

## Everything is sharp

20 August 2026. Vishnu, after looking at the step markers and switches: *"all
need to be sharp, all entirely, that is the only change."*

Every radius token set to `0` — `sm`, `md`, `lg`, `pill`, `circle`. That turns
the whole system square: cards, panels, inputs, buttons, badges, tags, avatars,
switches and their knobs, step markers, status dots, the tag remove control, the
loading spinner.

**The change was five lines.** Nothing in `components.css` or `sections.css`
hardcodes a radius; every one reads a token. This is the clearest demonstration
so far of why the token layer exists — a system-wide visual decision cost five
edits and is reversible with five more. The previous scale was 4px, 9px, 20px,
999px, 50%.

### Also updated, because they had gone stale

- **`foundations.html`** showed five corner options. There is one now, so the
  section says that instead of rendering five identical squares.
- **`signature.html`** had a corner-radius comparison and a dashed specimen
  overriding the radius to 2px. Both removed — the corner is documented once.
- **`audit.html`** carried eight hardcoded corners in its own page furniture,
  written before the system existed. Removed.

### One consequence, stated rather than buried

**Radio buttons are now square, the same shape as checkboxes.** They remain
distinguishable by their contents — a tick for a checkbox, a filled square for a
radio — but the round-versus-square shorthand for "pick one" versus "pick many"
is gone. That is a real cost of full consistency. Restoring only that shape is
one token: (secret removed) 50%`.

### Verified

All five gates after the change: conventions pass · contrast 1,849 text elements
across 7 pages, 0 failures · accessibility 7 pages, 0 problems · behaviour 30 of
30 · proof still holds. A computed-style sweep confirms **zero** elements with a
non-zero corner on any of the seven pages.

## Phases 4 to 7 — finishing it

20 August 2026. Vishnu: "do fully." The four items listed as outstanding are
now done, and doing them found five more bugs in the system.

### Added

- **`tests/check-a11y.js`** — an accessibility gate covering what a contrast
  gate cannot: accessible names on every control, alt text, heading order, one
  h1, ARIA references pointing at elements that exist, unique ids, focusable
  elements not trapped inside `aria-hidden`, landmarks, `lang`, tab-strip
  wiring, `th` scope, table captions, and positive `tabindex`. Written rather
  than pulled from a library: no network dependency, and every rule can be read
  and argued with.
- **`tests/proof-page/`** — a real araCreate Academy page, and
  **`tests/check-proof-page.js`** which proves it uses no custom CSS: no
  `<style>` block, no inline style attribute, every class defined in `src/`.
- **`releases/starter-kit/`** — a new site ready to fill in, 42 `REPLACE`
  markers, `src/` expected beside it. `make starter` copies it out.
- **`docs/guidance.md`** and a generated **`guidance.html`** — when to use each
  component and, more usefully, when not to. Built by
  `scripts/build-guidance.py`, which `make build` runs.
- **`.ac-surface-accent`, `.ac-surface-subtle`, `.ac-surface-raised`** — the
  proof page wanted all four surfaces reachable the same way. Only
  `.ac-surface-inverse` existed. A surface utility that exists for one of four
  surfaces is a quarter of a feature.
- **`--ac-grey-800`** — `#383838` had been sitting raw inside `base.css`.

### Five bugs, found by doing the work rather than by inspecting it

1. **Six demo inputs in the gallery had no accessible name**, and four were
   labelled by placeholder alone. The gallery was modelling the exact mistake
   the guidance warns about.
2. **Three `h1`s on the components page** — the hero and 404 specimens were
   injecting document structure into a page that is not that document. A
   specimen shows appearance; it takes the class without the heading semantics.
3. **`h2` followed by `h4`** on the home page. Screen reader users navigate by
   heading level, so a skipped level is a broken index.
4. **Eighteen `th` elements with no `scope`** across the signature and audit
   pages, and the audit page had **no `main` landmark**.
5. **The inverse surface never re-pointed the surface tokens.** It re-pointed
   text, borders and code, but not `--ac-surface-page` — so any component that
   paints itself with the page colour stayed light inside a dark band while its
   text turned white. The step markers in the proof page’s dark section rendered
   at **1.08:1**. Fixed for the inverse and accent surfaces both, which closes
   the whole class of bug rather than the one instance.

**Bug 5 is the argument for Phase 7.** Four gates passed for a whole build with
that fault sitting in the foundations. It surfaced the moment a real page put a
real component on a dark band. A system nobody has built with is a guess.

### Verified

Five gates, all passing: conventions · contrast (1,851 text elements across
7 pages, 0 failures, 7 declared exemptions) · accessibility (7 pages, 0
problems) · behaviour (30 of 30) · proof (no custom CSS).

The starter kit was copied out to a separate folder and served as a real new
site: 51 text elements, 0 contrast failures, 0 accessibility problems.

### Still not done, and worth saying plainly

A pass with a **real screen reader**. `check-a11y.js` catches missing names and
broken references; it cannot tell you a label is confusing or an order is
illogical. That needs a person and VoiceOver.

## Phase 3 — the component library

Added on 19 August 2026, after Vishnu said plainly that what existed was "not a
proper DS". He was right: there were foundations, signature devices, docs and
three test gates, and not one button.

### Added

- **`src/components.css`** — 24 component families. Button (5 variants, 3 sizes,
  6 states), field, input, checkbox and radio, switch, badge and tag, avatar,
  icon, card (6 kinds), accordion, tabs, breadcrumb, pagination, table, alert
  and toast, modal, dropdown, tooltip, progress, stat, testimonial, pricing,
  steps, logo strip, plus a deliberately short utility list.
- **`src/sections.css`** — 11 whole page sections. Header and navigation, hero,
  service list, team grid, project grid, blog listing, CTA band, FAQ, contact,
  footer, 404.
- **`src/components.js`** — tabs, dropdowns, modals, mobile nav, table sorting,
  toasts, tag removal, alert dismissal, progress mirroring. No dependencies.
- **`docs/components.html`** — the library, live, with markup, states and the
  reasoning under each one.
- **`tests/check-components.js`** — a behaviour gate driving 30 interactive
  paths, wired into `make test`.
- **`--ac-scrim`** token for the modal backdrop.
- **A favicon** on all five docs pages, as a data URI. This removed a 404 that
  the behaviour gate had been reporting — fixed by adding the missing thing
  rather than by widening the filter.

### Built on the platform rather than around it

Accordions are `<details>`, so they work with the script absent. Modals are
`<dialog>`, so focus trapping, Escape and the backdrop come from the browser.
Switches and checkboxes are real inputs with `appearance: none`. What is left in
JavaScript is only what HTML has no element for.

**The old menu bug is designed out, not patched.** The template covered the
current-page menu item with an invisible click-blocker; because every downloaded
page was `index.html`, 27 links matched "current" at once and the whole menu
died. The new header marks the current page with `aria-current="page"` and styles
it. Nothing is ever covered by an invisible layer.

### Three bugs found and fixed during the build

1. **A raw hex in `components.css`** — the modal backdrop. My own first rule,
   broken in my own file. Now `--ac-scrim`.
2. **The breadcrumb separator used the divider grey as text**: 1.67:1. A border
   colour is not a text colour; they are separate tokens precisely so this
   cannot happen, and I did it anyway.
3. **Card body copy rendered bold.** A card that is a link inherited `base.css`'s
   link typography — 12px, weight 600 — so every paragraph inside a card-as-link
   came out bold. **Both automated gates passed while this was broken.** It was
   caught by taking a screenshot and reading it. A gate tells you what it was
   told to look for; it does not tell you the page looks wrong.

### Verified

Conventions gate: pass. Contrast gate: 1,406 text elements across five pages,
0 failures, 7 declared exemptions. Behaviour gate: 30 of 30, including numeric
table sorting, keyboard tab strips, Escape restoring focus, the mobile menu at
phone width, and no sideways scroll at six widths.

### Also decided

`aria-busy` labels join disabled controls as a documented contrast exemption — a
loading button hides its label on purpose, and the requirement applies to text
that is displayed.

BEM (`__element`, `--modifier`) is recorded in the README as a **declared
deviation** from strict param-case. The conventions gate had been accepting
`--modifier` while rejecting `__element`, which was simply inconsistent. It now
enforces exactly BEM and nothing looser.

## [1.2.0] — 2026-08-19

### Added

- **Scroll-progress bar** (`.ac-progress`). Opt-in per page. Tracks the
  scrollbar exactly rather than easing behind it. `--thick`, `--strong`,
  `--under-bar`.
- **Horizontal scroll gallery** (`.ac-scroller`). Native scrolling with snap
  points — drag, swipe or arrow keys. `--wide`, `--narrow`, `--bleed`. Only
  becomes a tab stop if it actually overflows. Scrollbar styled yellow rather
  than hidden, because on desktop it is the only thing saying "draggable".
- **Sticky side text** (`.ac-sticky-side`, `.ac-split`). A heading that stays
  put while the column beside it scrolls. Goes static below 991px, where there
  is no adjacent column and a pinned heading just covers content.

### Changed

- **Signature edge is now dotted, not dashed, with square corners** —
  `--ac-edge-dash-style: dotted`, `--ac-edge-radius: 0`. Decision of
  19 Aug 2026, taken after reviewing all four forms rendered side by side.
  A deliberate departure: the live site is dashed with a 1–2px radius, so
  aracreate.group will look slightly different from the new sites until it is
  rebuilt. Reversible with those two tokens.
- **The edge is applied by default** to `.ac-panel`, `.ac-card`, `.ac-modal`,
  text inputs, `textarea`, `select`, `table`, `blockquote`, `figure img` and
  `dialog`. `.ac-edge-none` opts out. Buttons deliberately excluded.
- Focused form fields now switch to a **solid** charcoal border. A dotted
  border and a dotted focus ring look identical, so a keyboard user could not
  tell which field they were in.

## [1.1.0] — 2026-08-19

### Added

- **The signature edge** (`.ac-edge`) — the most distinctive device on
  araCreate, found in 38 rule blocks on the live site as
  `border-style: dashed dashed solid solid`. Modifiers for which corner stays
  closed (`--mirror`, `--top`, `--top-mirror`), form (`--thick`, `--dotted`,
  `--square`, `--round`), emphasis (`--strong`, `--faint`, `--accent`),
  interaction (`--interactive`), and joining (`--join-*`, `.ac-edge-row`).
- `.ac-dash` — the 55px rule above a heading. From `.dash`, 122 uses.
- `.ac-eyebrow` — the uppercase kicker. Charcoal on light, yellow on inverse.
- `.ac-underline` — the animated wipe-in underline. From `.hover-underline`,
  2,259 uses. `--persistent`, `--thin`, `--bold`, `--accent`, plus
  `.ac-underline-static`.
- `.ac-rule`, `.ac-rule-v` — hairlines.
- `.ac-bleed`, `.ac-band`, `.ac-bleed-inner`, `.ac-bleed@sm` — edge-to-edge.
- `.ac-marquee` — endless horizontal scroller, CSS only, pauses on hover,
  ends fade rather than clip.
- `.ac-reveal`, `.ac-reveal-line`, `.ac-reveal-group` — scroll reveals, the
  self-drawing line (from `.arrow-line`, 436 uses), and staggered groups.
- `.ac-sticky-bar` — the shrinking fixed header. 90 / 80 / 75px.
- `.ac-dot` — the loader dot.
- `signature.js` — about fifty lines, no dependencies. Replaces behaviour that
  on the live site requires Webflow’s 2.4 MB script plus jQuery.

### Fixed

- `.ac-eyebrow` created because the preview page had yellow eyebrow text on
  the light canvas at **1.55:1** — the yellow rule broken one turn after being
  written. A rule in prose gets broken; a rule in a component cannot be.
- Marquee duplicates carry `aria-hidden` **per item**. An earlier version put
  it on a clone wrapper that was then discarded, so a screen reader would have
  announced every item twice. Copies also get `tabindex="-1"` and lose their
  `id`s.
- `.ac-bleed` uses a measured `--ac-vw` rather than `100vw`, which includes the
  scrollbar and is the usual cause of a few pixels of horizontal scroll on
  full-width sections.

### Notes

- Marquee seamlessness is arithmetic, not tuning: the track translates `-50%`,
  which only loops cleanly while `padding-right` equals `gap`. Both are
  `--ac-marquee-gap`. Do not change one without the other.

## [1.0.0] — 2026-08-19

First version. Foundations only.

### Added

- `tokens.css` — 112 tokens in two layers. **Primitives** named for what they
  are (`--ac-yellow`, `--ac-grey-600`), **semantic** named for what they are
  for (`--ac-text-default`, `--ac-action-bg`). Components use only the second
  layer, which is what makes a dark theme later a change to one block.
- `base.css` — element defaults, so plain HTML is on-brand with no classes.
  Includes the global `:focus-visible` ring, `prefers-reduced-motion` handling,
  `.ac-sr-only` and `.ac-skip-link`.
- **Inverse-surface context** (`data-ac-surface="inverse"`). Any dark band
  re-points its own text, border, code and focus colours, so components need
  no dark variant. Added after inline `<code>` on the charcoal header rendered
  charcoal-on-charcoal — **1.00:1, invisible**.
- Brand colours taken from araCreate’s own logo files: yellow `#f9bf3b`,
  grey `#555555`.
- Type locked exactly to the live site: Poppins, 36 / 33 / 31 / 28 / 21 / 16px.
- Spacing named on the ten-based ladder already there by instinct, with the
  pixel size in the token name (`--ac-space-20` = 20px).
- Corners 4 / 9 / 20px, one shadow, four durations, six breakpoints.
- Empty documented `[data-ac-theme="dark"]` block — the door left open.
- `tools/check-contrast.js` — the accessibility gate.

### Changed from the live site — three repairs

- Twenty greys merged to five. Merged **by role, not by hex distance**: the
  audit found `#969696` was muted text while `#cecece` was a border, so a
  nearest-colour merge would have destroyed one of them.
- `--ac-grey-450` (#6f6f6f) introduced. The site used `#969696` and `#999999`
  for muted and placeholder text; `#969696` measures **2.69:1** on the canvas
  where 4.5:1 is required. #6f6f6f is the lightest grey that passes (4.61:1).
- Button label moved from `#555555` to charcoal. Grey on yellow measures
  **4.45:1** — it misses 4.5:1 by 0.05. Charcoal on the same yellow is 8.11:1
  and is visually almost indistinguishable.

### Removed

- Webflow factory defaults: `#3898ec` focus blue, `#0082f3` link blue,
  `#ffdede` error pink.
- Duotint leftovers `#2f3545` and `#2e419e` — the last trace of the template’s
  palette in araCreate’s code.
- The jQuery dependency. Every interaction on the live site requires it.

### Known deviations, locked by decision

Heading ladder (36/33/31/28px, ~3px apart), link size (12px) and body weight
(Poppins Light 300) are preserved as-is at Vishnu’s instruction, and recorded
in `tokens.css` so nobody assumes they were an oversight. Each is one token.

## Before 1.0.0 — the audit

Measured 72 pages (19 from aracreate.group, 53 from the Duotint template),
863 KB of stylesheet, 10,042 rules, 48,224 elements.

Findings that shaped the system: 76% of the site’s stylesheet is dead (3,182
classes defined, 813 used); twelve components exist twice with a `-2` suffix and
in two cases the copy has overtaken the original; 55 rules hard-code a brand
colour despite the variable existing; `.container` appears in 47 distinct
selector combinations.

**One miss, worth recording:** the audit extracted border *colours* but never
border *styles*, so the signature edge — the single most distinctive thing on
the site — went unreported until Vishnu asked for it directly. Any future audit
must enumerate style properties, not just colours and sizes. Distinctiveness
does not live in colour values.
