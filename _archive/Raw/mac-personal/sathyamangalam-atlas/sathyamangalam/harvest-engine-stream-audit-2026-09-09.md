# Harvest Engine Stream Audit — 2026-09-09

**Scope:** every source stream in `harvest-engine/src/streams/*.js`, cross-referenced against `harvest-engine/sources/*.json`, the stream registry (`src/streams/index.js`), and the live production Cloudflare D1 database (`harvest-engine-db`, queried read-only via `wrangler d1 execute --remote`) and `wrangler secret list` (names only, no values printed). **Method:** for every stream, `rows_written` was checked run-by-run against reported `status` — a "success" status with `rows_written = 0` on every run is treated as evidence of silent failure (dedup-freeze pattern), not as evidence of health, per this project's known history of that exact bug class. Dates below are real `started_at` timestamps from `job_run` rows, not claims from status reports.

**Correction to the brief's premise:** the wrangler.toml top-of-file secrets comment (which says `BHL_API_KEY`, `WDPA_API_KEY`, `DATA_GOV_IN_API_KEY` are all "NOT yet obtained") is **stale**. Live `wrangler secret list` shows `BHL_API_KEY`, `DATA_GOV_IN_API_KEY`, `EBIRD_API_KEY`, `FIRMS_MAP_KEY`, `GEE_SERVICE_ACCOUNT_JSON`, and `IUCN_API_KEY` are all actually set in production. Only **`WDPA_API_KEY` is genuinely missing** — confirmed independently by the secret list and by every `wdpa` job_run's `errors_json` saying so.

**Stream count:** 29 streams are wired into the cron/queue registry (`STREAMS` in `src/streams/index.js`). Two additional files under `src/streams/` — `overpass-boundary.js` and `gee-geometry-check.js` — exist and have `job_run` history but are **not** in the registry; they were one-off diagnostic/setup scripts run manually once (2026-08-25), not recurring streams. `gee-computations.js` is a pure-function library imported by `gee.js`, not a stream itself. Total distinct stream names with real `job_run` history: 33 (29 registered + 2 one-off diagnostics + `coarsen-verification`, another one-off script not tied to a `streams/*.js` file at all).

## Test suite caveat

`harvest-engine/test/*.test.js` (5 files: gee-request-hash, job-run-status, layer-review, place-identity, species-name) were not run as part of this read-only audit, and in any case passing unit tests would not prove the production dedup-freeze failures above are absent — none of the 5 test files test the actual write-vs-dedup interaction that this audit found broken in 10 of the 29 registered streams (gbif, core, bhl, wikidata, lgd, ntca, wii, historical-text, mongabay-india, toi-coimbatore, plus thehindu-tn frozen after one write). This is exactly the gap the brief's background flagged: tests can pass while production silently never writes real rows.

## Summary

**8 of 29** registered streams are actually healthy right now (dummy, ebird, inaturalist, crossref, semanticscholar, europepmc, unpaywall, ia-scholar, overpass, firms, gee, census, bhuvan — note: several of these are stale by 1–2 weeks but did write real data and are not masking failure). Correcting to a stricter count of streams with *no* open concern at all (excluding staleness flags): **dummy, overpass, unpaywall, firms, gee, census, bhuvan, erode-nic** are clean. Counting generously (healthy + healthy-but-stale, i.e. anything that has ever demonstrably written real rows and shows no active error): **13 of 29** streams are healthy. **11 of 29** streams report "success" or "partial" while having written zero (or effectively zero) real rows across their entire run history — silently broken. **5 of 29** streams are honestly blocked (openalex: quota/429; shodhganga and forests-tn: unreachable robots.txt on the origin site; wdpa: missing API key; management-plan: missing R2 prerequisite file).
