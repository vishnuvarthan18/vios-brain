This is the only prompt needed. It builds, tests, and ships the sellable desktop app end to end, without stopping to ask questions.

Status as of 2026-08-05: already run once, v1.0.0 shipped. Kept here for reference / future re-runs (e.g. a v2 build).

## Before this can start

Nothing. No accounts, no signups, no credentials file to wait on. This product is sold fully offline — payment is collected manually by Vishnu outside the app, and licensing is a self-contained signed-key scheme built in Task 4 (see CURSOR_BUILD_PLAN.md). `PRODUCT_SETUP.md` and `product-details.txt` are obsolete (old Lemon Squeezy plan, dropped) — ignore them. `server-details.txt` and any old Oracle/DigitalOcean files are also leftover from an earlier direction and no longer apply.

Start immediately.

## Ground rules

1. **Do not stop to ask the user any questions.** If something is ambiguous, pick the standard/reasonable choice, write one line in README.md explaining what and why, and keep going.
2. **Read `CURSOR_BUILD_PLAN.md` and work through Task 1 through Task 7, in order, back to back**, without pausing for approval between them. Treat each task's "Done when" line as a self-check, not something to ask the user to verify.
3. **No shortcuts on licensing.** No bypass, no hardcoded test key that works in the shipped build. The HMAC secret and the signature check are what stand between "sellable" and "free for everyone" — treat it as load-bearing.
4. **Generate any secrets/local signing needed yourself** (e.g. the HMAC secret, random values, local dev certs) — never leave a blank the user has to fill before the app runs.
5. **Work entirely inside this project folder.** Don't touch anything else on the machine. Only `whatsapp-sender-app/` should ever be tracked in or pushed to the product's GitHub repo — never commit `frontend/`, `reference/`, `scripts/`, or any file containing real personal data (e.g. test-contacts.csv).
6. **Task 6 (the end-to-end test pass) is mandatory, not optional.** Do not report the build as finished if any of its 7 steps fail — fix and re-run instead. Do not mark a step PASS if it required a real device (phone, second computer) that wasn't actually available — say so plainly instead.
7. If something genuinely fails after two reasonable attempts to fix it (a dependency that won't install, a platform-specific packaging issue), stop, write exactly what failed and what was tried into `BUILD_LOG.md`, and move on to whatever else can still be completed rather than getting stuck.
8. **Never delete or rewrite files outside the tracked git repo without flagging it first.** Files like `PROJECT_CONTEXT.md`, `CURSOR_BUILD_PLAN.md`, and this file live alongside the repo for human/AI continuity — they are not part of what ships and should never be touched during cleanup passes.

## Definition of done for the whole build

- App runs locally, connects to a real WhatsApp account via QR, stays connected across restarts.
- CSV upload, tag-based message editor, and live-preview all work.
- A real test send goes out to a few real contacts with correct delays and an accurate live status table.
- Both license types (one-time and subscription) correctly gate access using keys generated by keygen.js, including correctly locking the app back out on an expired subscription key — all without any internet connection.
- Windows and/or Mac installer builds successfully (whichever platform Cursor is running on, at minimum).
- `TEST_RESULTS.md` shows all 7 Task 6 steps passing.
- `keygen.js` runs standalone and produces working keys.
- `RESULT.md` exists summarizing all of the above, plus the manual sale-to-delivery steps for Vishnu and a customer-facing install/activate paragraph.

Print a short final summary as the last message once everything above is true.
