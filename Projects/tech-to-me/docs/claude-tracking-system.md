# Progress Tracking System

How pace actually gets measured, not just estimated. This doc is the mechanism; full-plan-timeline.md's "Speed log" is where the conclusions land.

## What gets logged, every session
Every time you study/practice (any domain, including sales), log these 4 things — takes under a minute:

1. **Date + domain + hours spent**
2. **What you actually did** (specific: "wrote 3 for-loops from scratch" not "studied loops")
3. **Self-rated confidence, 1–5** on what you just did (1 = still confused, 5 = could teach it)
4. **One thing that was hard** — the actual sticking point, in your own words

Log this here in chat as you go ("did 45 min on loops today, wrote 3 examples, confidence 3, still confused about when to use for vs while") — I'll record it into the relevant domain doc's progress log. You don't need to write it formally, just tell me.

## Weekly rollup (every 7 days, ~5 min)
At the end of each week, answer 3 questions and I'll log it:
- Total hours actually spent this week, vs. your 7–10 hr target
- Which phase are you in, and did you finish what the plan expected for this point?
- Confidence trend: are the daily confidence ratings climbing, flat, or dropping?

## Checkpoint (every 4–6 weeks) — feeds the timeline
This is where speed actually gets judged, using the weekly rollups:
- **Landed vs. logged:** did the confidence ratings for this phase's topics actually reach 4+ (real understanding), or did you move on at 2–3 (hours logged, skill not landed)? This matters more than hours.
- **Pace vs. plan:** compare actual phase completion date against full-plan-timeline.md's assumption for this point.
- **Verdict:** ahead / on pace / behind — written explicitly into full-plan-timeline.md's Speed log, with the timeline's milestone months adjusted if drift is real (not cosmetic).

## Skill checks (end of each phase, not each week)
Before marking a phase "done" in a domain doc, a quick real test — not a formal exam, just proof it landed:
- Software: explain or write a small working example from memory, no AI help, for the phase's core concept
- Electronics: predict a simple circuit's behavior before measuring it, then verify with a multimeter
- Mechanical: explain a design tradeoff out loud in your own words (e.g. why this material over that one)
- Strategy: write a 3-sentence hype-vs-substance verdict on a real product, unaided
- Sales: apply the skill in one real (even tiny) conversation, not a hypothetical

If a phase can't pass its skill check, it's not done, regardless of hours logged or calendar time passed — go back, don't advance the phase in the domain doc.

## Where it all lives
- **Daily/session logs** → each domain's own doc, "Progress log" section (short entries, dated)
- **Weekly rollups** → same domain doc, summarized weekly rather than daily-by-daily once there are many entries
- **Checkpoint verdicts + timeline adjustments** → full-plan-timeline.md, "Speed log" section
- **This doc** → the process itself; update only if the tracking method changes, not with actual progress data
